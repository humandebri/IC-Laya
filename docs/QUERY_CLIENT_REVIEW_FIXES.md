# queryクライアントと提案判定のレビュー対応

2026-10-01、クライアント側の4件を修正した。canisterのWasm、モデル、Candid APIは変更していない。入力を短くする処理や新たな量子化は追加していない。

## 一時的なHTTP失敗の再試行

HTTP status 429/502/503/504を再試行対象にした。応答が成功するまで同じ要求バイト列を再送し、既存の再試行上限と待機を維持する。HTTP 400等の恒久的なエラーは、メッセージにtransportが含まれていても再試行しない。失敗要求は従来どおり別集計。途中状態のディスク保存・再開機能はこの変更には含まない。

|入力tokens|F32|INT8|

66/67/68/69/70/71/72/73/79/80/81/87/88/89/90/91/95/96 tokensの18長で、F32/INT8両形式を7選択肢で比較した。qtypeは長さmodulo 3で切り替えた。36ケースすべてで旧設定とlogits完全一致、失敗なし。最大handler命令数はF32 4,497,419,225、INT8 4,272,820,294。入力はCLS、7 MASK、長さ調整用の固定token、SEPからなる境界校正用データで、精度を測る自然文の集合ではない。

実際の68-token入力も変更後のコードで確認した。F32は10→5 query、4,393,491→1,952,824 bytes（約55.6%減）。INT8は10→6 query、714,773→398,885 bytes（約44.2%減）。形式ごとの旧logitsと完全一致した。93-tokenの実入力もF32 10→8 queryで一致、INT8は保守的な3段を維持する。

通信量は成功したCandid要求＋返信continuation blobで、HTTP等の外側・返信のCandid envelope・最終logitsを除く。handler命令数はCDK decode/encodeを含まない。キャッシュを制御しておらず、本番の速度や全入力の上限内実行は保証しない。失敗時の幅半減・auto_cap維持は残し、未知のpackには自動校正を適用しない。

固定pack SHA256は`bb70b3f0f2806bef5d4b670f44bb606892067fc0ebd928bd682b98ebdb2dc092`、測定Wasmは`0x84d7dfd1ffcf72467cc6af309a80585ea658387e4f2772c8f2937114c409c5d5`。

再測定用ツールは旧設定と現行設定を同じ入力で比較し、モデルとWasmを前後で確認する。warmな専用local canisterが必要。既存結果を上書きしない。


## 全テンソル復元を省いた応答検証

`inspect_state()`はヘッダーだけを保持し、圧縮bodyを最大64KiBずつ展開・破棄する。F32テンソルのbyte shuffleを復元しない。申告長、出力上限、zlib checksum/EOF、末尾データ、codecと状態形式の一致を最後まで検証する。次のqueryには受け取ったwire blobをそのまま渡す。生の状態と既存の`unpack_state()`も維持する。

省くのはクライアント側のコピーとメモリ確保であり、この変更だけでネットワーク転送量が減るわけではない。CLIの文字列化やRust側のcodecコピーは今回の修正範囲外。

## 提案の変更ごとの補助判定

`--with-laya`は単一の提案ラベルから`laya.assessments`の項目別出力に変更した。最低投票期間、最大ロック期間、最低stakeは、それぞれの制度条件と提案作成時の旧値・新値を渡す。期間の減少も対象にし、未変更値は`unchanged`として保持する。

その他の指定されたパラメータも削除せず、旧値・新値と`unsupported`を返す。旧値を読めない場合は不明と明示する。mintは数量・受取principal/subaccountを根拠に保持し、供給量や既存保有量を推測しない。入力が128tokensを超えたり、ある項目のモデル実行に失敗したりしても、その項目の根拠を残して`unavailable`とする。黙った切り捨てや別項目の結果の破棄はしない。

`coverage_complete`は各指定項目に判定または未変更の確認があるかを示す。情報が十分であることや正解率を示す値ではない。`aggregate_label`はnullとし、項目別logitsから提案全体の危険確率を作らない。数値ルールのpriorityは変更しない。この出力形式は従来のトップレベル`laya.label/raw_logits`からの変更なので、利用側はassessmentsへ移行する必要がある。

617では最大ロック期間と最低投票期間の両方のnative実行を確認した。モデルの分類は引き続き未校正で、一般的な精度向上を確認したという意味ではない。歴史的BOOM DAOベンチは明示的な`_legacy_laya_context()`で元の入力を再現し、過去の数字と新しいpromptを混ぜない。

Python全96テスト成功。HTTP再試行の同一バイト・上限・恒久的エラー、圧縮body後半の破損と過大長、項目別根拠の保持・モデル失敗・過長入力を検証した。Rustコードは変更していない。
